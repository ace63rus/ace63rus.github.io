РТС-тендер в Tendeo: из чего состоит подключение

Прочитал регламент на десять страниц и файл с примером данных. Ниже — как источник встаёт в ваш пайплайн, что я проверил на площадке живьём и где нужен ваш ответ. Три вопроса внизу, остальное уже понятно.

Куда встаёт источник

1
Парсер забирает данныепо вашему регламенту
Класс RtsTenderParser с ключом rts_tender. Отдаёт элементы через yield, в payload только сырые данные источника, без счётчиков и времени скачивания. Ничего в общем пайплайне менять не нужно — очередь, повторы и дедупликация уже есть.
2
Нормализатор раскладывает по полямпо вашему регламенту
Класс RtsTenderNormalizer с тем же ключом: название, цена, даты, статус, заказчик по ИНН, регион и город через App\Geo, документы. Повторная нормализация обновляет существующий тендер и не плодит документы.
3
Запись Source и расписаниесамо подхватится
Источник создаётся в админке с ключом rts_tender и попадает в общий обход через ParseActiveSourcesMessage. Отдельное расписание не требуется.
4
Откуда берём данныевопрос
Два пути, и они разной стоимости по времени. Выбор зависит от того, есть ли у вас доступ к API площадки.

Развилка: как забирать

А. Через API площадки
Быстро, стабильно, без браузера. Нужен токен и договор с РТС. Если токен есть — это лучший путь и он заметно сокращает срок.
Б. Через браузер
Работает уже сейчас, без договора. Медленнее: страница открывается в реальном браузере, данные снимаются с готовой страницы. Так мы берём Wildberries и Ozon, схема отработанная.
Что проверил живьём 26 октября. Поиск по 44-ФЗ открывается без авторизации и отдаёт всё, что нужно: номер закупки, название, начальную цену, обеспечение, статус, даты, лоты с ОКПД2 и количеством, организатора с ИНН и контактами, регион и адрес поставки. По запросу «компьютер» — 117 извещений. Прямой HTTP-запрос площадка режет защитой, в браузере страница открывается нормально. Внутренние JSON-методы у них есть, но списка закупок среди них нет — список приходит готовой страницей.

Как идём: три блока

1
Список извещений 44-ФЗс этого начинаем
Парсер собирает список: номер, название, цена, даты, ссылка. Пагинация, стабильный externalId, защита от дублей. Тендеры появляются в админке, расписание подхватывает источник само.
2
Карточка закупки
Догрузка деталей: лоты с ОКПД2 и количеством, заказчик с ИНН и КПП, контакты, регион, адрес поставки, документы.
3
Нормализатор, тесты, выкатка
Раскидка по полям Tender, заказчик по ИНН, регион по ОКАТО, документы. Фикстуры в tests/Fixtures/rts_tender/, тесты, прогон на проде, запись в ARCHITECTURE.md.
Почему блоками. Каждый блок заканчивается тем, что видно в вашей админке и можно проверить. Первый блок — это проверка: вы смотрите, как я работаю, на своём коде, за небольшие деньги. Не подошло — дальше не идём, и никто ничего не потерял.

Три вопроса

1
Есть ли доступ к API площадки?
Токен по договору с РТС. В вашем примере кода стоит переменная с токеном — если доступ есть, второй и третий блок пойдут заметно быстрее и дешевле.
2
Дадите доступ к репозиторию и тестовому окружению?
Нужны код, ARCHITECTURE.md и возможность поднять локально через docker compose. Без этого работу начать нельзя, а доступ раньше оплаты — обычная практика по вашей же инструкции.
3
44-ФЗ и 223-ФЗ с площадки — точно нужны?
Эти извещения уже приходят из ЕИС, а ЕИС-парсер у вас работает. Новые данные дают только коммерческие закупки, маркет малого объёма и 615 ПП. Если брать с РТС всё — часть базы задублируется.
